# STM32 PWM Buzzer Music Player

This project implements a music player on an STM32 microcontroller using hardware PWM to drive a passive buzzer. Musical notes are generated by configuring a timer’s auto-reload register (ARR) to produce precise square-wave frequencies. The system supports real-time pitch shifting using external interrupts.

---

## Hardware Components

- STM32 development board (NUCLEO-L476RG)
- Passive buzzer  
  - Connected to **TIM2 Channel 3 PWM output**
- Two push buttons  
  - **PB5**: Pitch up  
  - **PA10**: Pitch down
- Jumper wires

![Circuit Schematic](bmpschem.png)
---
## Timer Configuration (TIM2, 32-bit resolution)
- PSC: 4
- Counter mode: Up
- PWM mode: PWM1
- Channel: TIM2_CH3
- CLK source: PLL-derived system clock

## System Overview

### Sound Generation (PWM)

- Uses **TIM2 PWM** to generate square waves
- Each note frequency is produced by updating the timer period (ARR), where ARR = (timer CLK/frequency) - 1
- Duty cycle (CCR) controls volume
  
### Melody Representation
- static const float frequencies[] stores note frequencies in Hz
- static const float durations[] stores note lengths in milliseconds

### Button Inputs (EXTI)
- PB5 increments pitch (upCount++)
- PA10 decrements pitch (downCount++)
- Pitches are shifted by one semitone: f_shifted = f_base × 2^(n / 12), where n = upCount - downCount
- 50 ms debounce window implemented to reduce input noise

### Playback 
For each note, the program will:
1. Apply pitch multiplier
2. Compute PWM frequency (ARR)
3. Set duty cycle (volume)
4. Start PWM output
5. Delay for note duration
6. Stop PWM

## FFT Note Extraction Pipeline

To generate note and duration data for the STM32 buzzer player, an offline Python-based FFT pipeline is used to extract musical information from an audio file. This allows real music to be converted into a sequence of frequencies and durations compatible with embedded playback.

The pipeline is implemented in `FFTNoteExtractor.py` and produces two text files:
- `notes.txt` — extracted note frequencies (Hz) -> frequencies[]
- `durations.txt` — corresponding note durations (ms) -> durations[]

These values are later embedded directly into STM32 firmware through the arrays defined above.

---

### 1. Audio Loading

```python
y, sr = librosa.load(wav_file, sr=None)
```
- Loads the WAV file at its original sampling rate
- Preserves frequency accuracy with no resampling

### 2. Harmonic–Percussive Separation (HPSS)
```python
y_harmonic, _ = librosa.effects.hpss(y)
```
- Separates harmonic content (pitched tones) from percussive noise
- Removes transients that would otherwise corrupt FFT peak detection
- Improves stability of detected note frequencies

### 3. Bandpass Butterworth Filter
```python
butter_bandpass(y, sr, low=250, high=1000)
```
- 4th-order Butterworth bandpass filter
- Passband chosen to isolate typical melody frequencies
- Smooth analog-style rolloff avoids ringing artifacts
- Removes low-frequency noise and high-frequency harmonics that may contribute to unwanted noise

### 4. Short-Time Fourier Transform (STFT)
```python
stft = librosa.stft(y_hp, n_fft=4096, hop_length=512)
```
- Converts time-domain signal into a time–frequency representation
- Large FFT size of 4096 improves the frequency resolution
- Hop length of 512 balances time resolution and overlap

### 5. Magnitude & Log Scaling
```python
magnitude = np.abs(stft)
log_magnitude = librosa.amplitude_to_db(magnitude)
```
- Logarithmic scaling reflects human loudness perception
- Prevents dominant notes from masking quieter peaks

### 6. Peak Detection Per Frame
```python
peaks, _ = find_peaks(frame, height=mean(frame) - 10)
```
- Peaks are detected in the frequency domain
- The strongest peak is selected as the dominant note
This yields a time-stamped sequence of detected frequencies

### 7. Note Grouping & Duration Estimation

(frequency, start_time) → grouped → (frequency, duration)

- Consecutive frames with similar frequencies are merged
- Frequency tolerance: ±2 Hz (can be adjusted)
- Duration filter removes short transients which may add undesired noise (< 80 ms, can be adjusted)
- Output durations are converted to milliseconds

### 8. Export for Embedded Use
```python
export_notes(...)
export_durations(...)
```
- Frequencies and durations are written to plain text, and values are later copied into the firmware as constant arrays
- Enables memory-efficient and deterministic playback on the MCU

## Why the FFT Is Performed Offline?

Real-time audio analysis using FFT is computationally expensive and poorly suited for resource-constrained microcontrollers. The STM32 platform is optimized for deterministic control and signal generation, not high-throughput spectral analysis.

Performing FFT offline enables:
- High-resolution FFTs with large window sizes
- Advanced noise reduction and harmonic isolation
- Stable and repeatable note detection
- Clean separation between analysis and playback

By moving signal analysis to a host computer, the STM32 firmware can focus entirely on **precise timing and waveform synthesis** using hardware timers.

## Recommended Workflow for Best Results

For the most accurate and stable note extraction, I recommend the following workflow

1. **Start with a Music Score**
   - Use a MuseScore (or another similar) score rather than raw audio when possible
   - MuseScore's editing software allows you to extract the raw melody from scores

2. **Remove Non-Melody Parts**
   - Delete bass lines, chords, and accompaniment tracks
   - Retain only the primary melody line to prevent overlapping frequencies

3. **Use a Pure Sine Instrument**
   - Set the melody instrument to a pure sine wave for best frequency detection results
   - This minimizes harmonics that can confuse peak detection in the FFT

4. **Export to WAV**
   - Export the score as a WAV file
   - Use a consistent sample rate (e.g., 44.1 kHz)

5. **Run FFT Extraction**
   - Process the WAV file through the FFT pipeline
   - Import the resulting frequencies and durations into STM32 firmware

This workflow significantly improves frequency accuracy and reduces false note detection, producing cleaner and more reliable embedded playback.

## Summary
This FFT pipeline converts real audio into a structured sequence of notes suitable for embedded systems. By separating analysis (Python + FFT) from synthesis (STM32 + PWM), the design achieves both accuracy and hardware efficiency.
